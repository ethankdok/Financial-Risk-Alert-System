# 案例故事線與官方法說 PDF 原型（2026-09-25）

## 研究問題與首個案例

問題：在事件被市場廣泛知悉之前，投資人當時能取得的公開文件中，是否存在**可被本系統指出並附上來源的風險線索**？「後來發現財報不實」不等於「系統一定能從當時公開資料發現造假」。陰性、資料不足、官方文件無法取得都是有效的實驗結果。

| 角色 | 公司與事實來源 | 預定切點 | 現階段結論 |
| --- | --- | --- | --- |
| 首個風險候選 | 康友-KY（6452，生技）。臺北地方法院 2024-06-17 一審新聞稿指出虛灌銀行存款、不揭露動產抵押及不實財報等事實；案件的後續司法程序須以最新裁判為準。https://www.judicial.gov.tw/tw/cp-1888-1108506-0b0a6-1.html | 先以 **2020-07-31** 作為試驗性的資訊截止日；逐筆核對 2020-08 前各文件真正公開日期。 | 官方事件來源已確認；**事件前法說 PDF 和原始版本財報尚未取得**，不能宣稱已可完整回測。 |

故事線草稿：康友事件後，回到 **2020-07-31 當天** → 對當日以前已公開的財報、重大訊息與法說資料建立版本化證據 → Financial Rules、官方文字與跨期變化分別分析 → 顯示具來源和時間的線索及「資料不足」→ 最後才對照後來的事件。此故事目前是**待驗證的研究設計**，不是已證明能提早發現造假的成果。

目前的半導體 company registry 與財務規則不支援 6452；若它通過資料可得性門檻，需另做跨產業範圍、財務欄位與規則適用性的設計，不能直接把半導體風險分數套上去。PDF archive CLI 可獨立記錄研究資料，但也不代表正式 API 已支援這家公司。

優先做兩張資料清單：

1. 6452 於切點前的 MOPS 原始財報版本、法說 PDF／逐字稿、重大訊息；每筆需官方 URL、發布日、下載日、文件 hash。下市與舊資料的可得性必須實測。
2. 2929 在切點前後的原始版本財報、重大訊息與法說資料；證交所另在 2020-11-11 公告其某項理財商品處分延遲輸入重大訊息，該公告可作另一種「資訊時效」驗證，但不可倒灌至 2020-06-30 的輸入。https://www.twse.com.tw/staticFiles/news/news/tsecnews/ff80808174fce5b30175b6397879025c.pdf
3. 2330 官方季度頁的兩期同類 PDF，用來檢驗下載、可選取文字、頁數、品質與版本。不可把逐字稿與投影片直接當同類配對。

案例納入門檻：官方可核對的事件、明確的公開切點、至少兩期同類型事件前文件、可取得的原始 PDF／財報、保留首次公開版本。未通過任一條件時標記 `NOT_BACKTESTABLE`，轉向下一候選。

康友與淘帝都能研究「資訊揭露可信度」，但它們分屬**不同產業**；目前不能據此聲稱已找到老師期待的「同產業多案例」。初步敘事選康友，淘帝是第二個對照風險候選；選定最終產業之前仍需蒐集同產業、文件齊全的其他案例。

## 取得與擷取的開發決策

目前未核實到提供**歷史法說 PDF 全文**的穩定官方 OpenAPI。TWSE OpenAPI 存在（https://openapi.twse.com.tw/），但不能把一般公司資訊／公告端點誤寫成法說 PDF API。MOPS 法說查詢入口是 `t100sb02_1`；實際下載連結及其 HTTP 回應仍需逐公司驗證。現有程式 `official_event_sources.py` 使用另一條 `t100sb07_1` 查詢路徑和公司 IR fallback，因此不能假設每個 metadata record 都是已下載的 PDF。

本次採「小範圍自行取得」：輸入一個人工確認的 MOPS／官方公司 IR 頁面，讀取其 PDF `<a>` 連結，下載有白名單的 PDF，核對 `%PDF-`、保存原件 SHA-256 和完整文字。命令：

```bash
cd fintrust_backend
python -m scripts.acquire_official_ir_pdfs \
  --ticker 2330 --company 台積電 \
  --page-url https://investor.tsmc.com/english/quarterly-results/2025/q4 \
  --output data/official-ir-pdfs --max-documents 3
```

`--ocr` 可選：需額外安裝 PyMuPDF、Tesseract 執行檔及對應語言包；掃描件 OCR 仍需人工抽驗。未裝時工具保留 PDF 與文字缺失狀態，不會產生假的擷取成功。該 CLI 的 archive 僅保存在本機忽略追蹤的 `fintrust_backend/data/`。雲端運行時須改成 GCS 原件儲存、Firestore metadata、權限與排程；本原型**未寫入雲端、未提供任意 URL 的公開 API、未啟用定時下載**。

現有 `official_document_extraction.py` 已可按需抽取文字，但通常截短；`official_event_ingestion.py` 目前對排程不預設擷取文件。新 archive 保存原 PDF 與全文，供後續選取同公司、相同文件類型且發布於切點前的兩期資料。交給 Data Shift 的契約至少要有 `ticker`、`company_name`、`document_type`、`period`、`published_at_verified`、`source_url`、`sha256`、`text`、`extraction_quality`。**組員完成新資料集與門檻校準前，不套用 STRUX JSD／Cosine 的舊閾值，也不顯示正式漂移風險。**

## 驗證邊界

本執行環境對 MOPS、台積電及聯發科網站的直接連線逾時／拒絕，故只完成受控 PDF fixture 的下載／擷取測試。官方站點的 live 下載成功率、MOPS 附件連結解析、2019–2020 年康友資料可得性仍未驗證。下一步在可連線的 Cloud Shell 或本機對 2330 兩期與 6452 事件前資料做實測，記錄原始 URL、HTTP status、文件數與擷取率；實測前不將案例定案為可回測。
